| Playlist position (provisional) | Concept | Increment in EventHub | Acceptance / experiment |

| 1 | Roadmap for backend from first principles | [Orientation notes](lectures/01-roadmap.md). | Explain course goals and product boundary. |
| 2 | Walk the path of a true backend engineer | [Learning approach](lectures/02-learning-approach.md). | Explain problem-first experimentation. |
| 3 | What is a Backend, how do they work and why do we need them? | [Backend and request lifecycle](lectures/03-what-is-a-backend.md). | Explain server, port, DNS, transport and HTTP roles. |
| 4 | Benefits of learning backend engineering from first principles | [First-principles benefits](lectures/04-first-principles-benefits.md). | Trace an unfamiliar backend and propose a debugging experiment. |
| 5 | [Understanding HTTP for backend engineers, where it all starts](lectures/05-http.md) | Native HTTP server, /health, simple in-memory event endpoints, methods, status codes, headers, HEAD/OPTIONS, cookies/CORS experiments as covered. | Inspect raw requests/responses with curl; compare success, 404, 405, preflight, HEAD with no body; explain caching and connection behavior. |
| 6 | [Routing](lectures/06-routing.md) | Handwritten router: method/path matching, parameters, grouped and versioned routes, explicit collision rules. | Static vs parameterized routes, constraints/order, 404/405, encoded paths and HTTP regression checks. |
| 7 | [Serialization and Deserialization for Backend Engineers](lectures/07-serialization.md) | Inspect and improve existing native HTTP JSON reader/writer; explore bytes vs text, DTO boundaries and format trade-offs. | Valid/invalid JSON, type errors, unsupported media type, body size, UTF-8 and prior HTTP/routing regressions; optional local format benchmark. |
| 8 | [Authentication and authorization for backend engineers](lectures/08-authentication-authorization.md) | User identity, login, safe password hashing, session/token comparison, role and ownership checks. | Reject unauthenticated or wrong-owner requests; distinguish 401 and 403; reproduce stale JWT claims and compare current-state checks and revocation. |
| 9 | [Validation & Transformation](lectures/09-validation-transformation.md) | Reuse and improve existing request validation, safe normalization, explicit writable fields and structured errors; synthetic pricing/source-of-truth exercise. | Reject malformed or unsafe inputs, prevent state mutation on invalid writes, verify safe coercion, server-derived totals and stale price comparisons; preserve earlier regressions. |
| 10 | [What are controllers, services, repositories, middlewares and request context?](lectures/10-application-layers.md) | Incrementally separate HTTP, business logic and storage; introduce/reuse middleware pipeline and request-scoped context. | Trace one request, test middleware short-circuiting, identity isolation, business logic without HTTP and pre/post-refactor regressions. |
| 11 | [Complete REST API Design](lectures/11-rest-api-design.md) | Design event resources, pagination, filtering, sorting, versioning and consistent status/error contracts. | Exercise CRUD, pagination bounds and method semantics. |
| 12 | [Mastering Databases with Postgres](lectures/12-mastering-databases-postgres.md) | Replace memory with SQL persistence, migrations, constraints, transactions and measured indexes; introduce connection pooling as appropriate. | Persistence across app restart, rollback, constraint violation, query plan; isolated atomic ticket-allocation experiment. |
| 13 | Caching | Cache popular event reads, TTL and invalidation; keep inventory authoritative. | Compare cold/warm latency and stale update behavior; cache outage. |
| 14 | [Task Queues and Background Jobs](lectures/14-task-queues-background-jobs.md) | Isolated mock ticket-confirmation job with producer, queue and independent worker; retries, recovery and duplicate-effect lab. Connect to real confirmed bookings only once that domain flow exists; defer expiry and ticket generation. | Worker restart/recovery, bounded backoff and duplicate mock-effect protection; diagnose enqueue/provider failures, and document cross-system atomicity limits. |
| 15 | [Full Text Search using Elasticsearch](lectures/15-full-text-search-elasticsearch.md) | Incremental attendee search on current event fields: parameterized ILIKE baseline, PostgreSQL FTS with GIN and ranking, then optional isolated Elasticsearch experiment with source-of-truth and freshness checks (requires owner approval for implementation). | Published/authorized results only; bounded query/pagination, ranking, no-match and typo/language checks, EXPLAIN/latency evidence, update lag and outage experiment if Elasticsearch is approved. |
| 16 | [Error Handling and Building Fault Tolerant Systems](lectures/16-error-handling-fault-tolerance.md) | Reuse central safe error contract and typed errors; bounded dependency timeout/retry, failure isolation, mock idempotency and liveness/readiness. | Simulate invalid inputs, DB and mock dependency failures; avoid infinite retries, duplicate effects and information leakage; verify regressions. |
| 17 | [Production-grade Configuration Management](lectures/17-configuration-management.md) | Central typed configuration boundary for existing API/worker, explicit precedence, strict startup validation, safe placeholders and one existing optional feature flag. | Missing/invalid settings reject startup; safe logs, isolated dev/test, flag behavior, precedence and regression checks. |
| 18 | [Logging, Monitoring and Observability](lectures/18-logging-monitoring-observability.md) | Reuse structured logger and request context; bounded HTTP latency/error metrics, one local trace, and existing mock worker telemetry. | Diagnose controlled slow/failing event requests and job attempts; verify context isolation, redaction, bounded cardinality, exporter outage and regression behavior. |
| 19 | [Graceful shutdown](lectures/19-graceful-shutdown.md) | Add bounded SIGTERM/SIGINT handling to the API and separate BullMQ worker; stop admitting work, drain in-flight requests/jobs, and close dependent resources safely. | Slow HTTP request during SIGTERM; active queue job during SIGTERM; repeated signal, deadline, cleanup-failure and SIGKILL/idempotency recovery experiments. |
| 20 | Security | Threat model, access control, secure cookies, rate limit, injection prevention and dependency review. | Negative auth/ownership and abusive input tests; no secret leakage. |
| 21 | Scaling I | Establish load baseline, profile queries and optimize evidenced bottlenecks. | Compare throughput, p95 latency, error rate before/after with workload and hardware recorded. |
| 22 | Scaling II | Multiple stateless instances and local reverse proxy/load balancing. | Requests reach replicas; kill one and observe recovery; shared persistence stays consistent. |
| 23 | Concurrency/parallelism | Booking contention, race-condition reproduction, locking/atomicity and asynchronous vs CPU work. | Many buyers compete for limited tickets; zero overselling and duplicate confirmation. |
| 24 | Object storage I | Move event images and ticket assets to local S3-compatible storage or equivalent. | Restart API; verify assets persist and metadata stays valid. |
| 25 | Object storage II | Direct/presigned uploads, private reads, large-file or multipart experiment. | Expired/unauthorized URL rejected; test size limits and failed upload. |
| 26 | Realtime | SSE/WebSocket ticket availability and booking updates. | Two clients observe changes, reconnect and reconcile with authoritative state. |
| 27 | Testing/code quality | Improve unit, integration, end-to-end and concurrency regression coverage. | Reproduce a defect with a test; verify fix and repeatable test execution. |
| 28 | Twelve-factor principles | Review config, processes, dependencies, logs, disposability and environment parity. | Run same build under different config; restart without losing durable state. |
| 29 | OpenAPI | Publish machine-readable contract and API docs. | Validate request/response samples and detect spec drift. |
| 30 | Webhooks | Mock payment callbacks with signatures, replay defense and idempotent state changes. | Reject invalid signatures; repeated/late callback cannot duplicate confirmation or oversell. |
| 31+ | DevOps/remaining curriculum | Containerize and automate checks, migrations and deployment/rollback when applicable. | Reproducible setup, health probe, tested deployment path. |

## After the backend curriculum
Owner reviews milestones, outstanding gaps, API and invariants. Only then select frontend stack, design attendee/organizer/admin screens, integrate real backend endpoints, verify full-stack workflows, and consider deployment. No frontend implementation now.
